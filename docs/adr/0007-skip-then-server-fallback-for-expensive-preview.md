# Skip the automatic client-side Render for expensive Templates, offer Render on server instead of auto-routing

A Template whose `for` loop reaches a `text()`/boolean-op call (`estimateComplexity`'s `hasExpensiveLoop` — the Thai character-roller's shape, 43 engraved cuts) can run past the client-side Render Worker's timeout, so the automatic client-side attempt is skipped for it entirely rather than run and likely killed (see `useRenderMesh`'s `skipAutoRender`). The user sees a call-to-action instead of a spinner: force the client-side attempt anyway, or Render on server, which reuses the fast Manifold-backed pipeline ADR-0006 already stood up for Export.

The alternative considered was auto-routing straight to server-side Render the moment a Template is flagged expensive, skipping the prompt. Rejected because it reopens the concurrency argument ADR-0004 already settled: an expensive Template being *auto-rendered on every Configuration tweak* turns every slider drag on it into a queued Container job, the exact "free client compute vs. costed server compute" line ADR-0004 drew, just redrawn around a different set of Templates instead of erased. Requiring an explicit click for both the client attempt and the server one keeps that line intact — Render on server is a deliberate, occasional action with the same cost shape as an Export, not a continuous one, which is also why it doesn't auto-refresh itself on further Configuration changes (see CONTEXT.md: Render on server).

The other alternative — building a Manifold-enabled `openscad-wasm` from source to fix the client-side engine itself instead of working around it — was deferred rather than rejected. Nothing here forecloses it; it's a separate, larger investment (an in-house Emscripten build pipeline with ongoing maintenance, since upstream `openscad-wasm` hasn't cut a release since 2022) that can replace this whole mechanism later if the case for it grows.

(It did: [ADR-0011](./0011-client-side-manifold-backend.md) moved the client engine to Manifold — turned out to be an official upstream build, not an in-house one — and [ADR-0012](./0012-remove-customer-skip-gate.md) retired this mechanism for the customer-facing Customize view on the strength of that. The Admin Panel's own live preview keeps it, for the separate reason this ADR's second paragraph gives.)
