# Cache the default-Configuration preview, precomputed headlessly in the render-worker Container

Every fresh visitor to a Template's Customize view pays the client-side engine's full cold-start-plus-CGAL-evaluation cost for the exact same input: `defaultConfiguration(template)`, since `CustomizeView` seeds state with it and `useRenderMesh` goes straight to openscad-wasm with no shortcut. That work is identical across every visitor of a given Template — nobody's first Render is personalized — so it's cached instead of repeated. On a successful Save, the render-worker Container is asked (fire-and-forget, via a lightweight message on the existing `render-jobs` queue rather than a tracked `export_jobs` row, since nobody polls this by ID) to compute the default Configuration's Mesh once and write the resulting STL to a fixed R2 key (`default-preview/{templateId}.stl`, overwritten in place on the next Save — no invalidation logic needed beyond that). `useRenderMesh` races a fetch of that key against its normal Worker-based render on a Customize view's first paint; whichever produces a usable result first wins, so a cache miss (a Template not yet warmed) costs nothing extra over today's baseline. A one-time backfill endpoint warms every currently-Listed Template's cache at rollout, since otherwise nothing benefits until its next unrelated Save. If the warm job fails, it fails silently — no retry, no Admin-visible indicator — because the fallback (today's live client Render) is already correct and this is a pure speed optimization sitting on top of it, not a source of truth.

The precompute reuses the render-worker Container's existing native-OpenSCAD path exactly as-is — the same `spawn("openscad", ...)` call, on the Manifold backend, that Render on server and an Admin's Export already run in production — rather than standing up a second rendering mechanism. This was not the original plan: it was scoped first for a headless *openscad-wasm* build (matching the browser's then-CGAL engine, to avoid a second backend feeding the Viewer, per [ADR-0001](./0001-always-render-exact-geometry.md)'s single-canonical-pipeline commitment), and a real, working headless-Node WASM path was identified (OpenSCAD's own official `NODERAWFS` Node build, published at `files.openscad.org`) before [ADR-0011](./0011-client-side-manifold-backend.md) made it unnecessary — once the client itself moved to Manifold, precomputing via the already-proven native container path stopped being a divergence at all: client, precompute, and Render on server now all agree on backend, and the one Render every customer is guaranteed to see first (the cached default) is on the same footing as every Render after it.

A cache hit deliberately overrides [ADR-0007](./0007-skip-then-server-fallback-for-expensive-preview.md)'s skip-gate for Templates flagged `hasExpensiveLoop`: that gate exists to avoid unprompted compute on the visitor's own machine, and fetching a cached result isn't compute — an expensive Template gets its CTA-only empty state replaced by an instant real Mesh whenever a cache entry exists, which is a strict improvement, not a reason to keep gating. Scope stays deliberately narrow to the default Configuration only: the parameter space beyond it is continuous, so a shared cache for arbitrary customer-chosen Configurations would mostly miss and isn't built here — and the Admin Panel's own live preview during editing never consults this cache at all, since ADR-0009 already established that an Admin always wants an on-demand, current result, not a possibly-stale cached one.
