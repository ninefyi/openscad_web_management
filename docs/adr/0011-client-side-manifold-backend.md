# Client-side preview switches to the Manifold backend

The client Web Worker now runs openscad-wasm on the Manifold backend (`--backend=manifold`), the same backend the server side has used since [ADR-0006](./0006-manifold-backend-for-server-side-render.md). Interactive parameter-tweaking — a customer dragging a slider, not just the first paint — was the one thing [ADR-0007](./0007-skip-then-server-fallback-for-expensive-preview.md)/[ADR-0010](./0010-cached-default-preview.md)'s work on the default-Configuration cache couldn't touch, since every Render after the first still had to pay CGAL's cost (ADR-0006's own benchmark: 90.1s CGAL vs. 0.47s Manifold on the same Template). Reviewing `openscad/openscad-playground` — the sibling official OpenSCAD project this whole line of investigation started from — showed it gets its own speed this same way: default-to-Manifold, nothing more exotic.

Mechanically, this swaps the vendored `public/openscad/openscad.js`/`openscad.wasm` for OpenSCAD's own official Manifold-enabled web build, published at `files.openscad.org` (checksum-verified against their own published SHA-256, not built or modified by this project) — the same artifact class `openscad-playground` itself consumes rather than building from source. `openscad.fonts.js` and the extra Thai `.ttf` fonts are untouched: font loading is pure Emscripten-FS writes, independent of which binary it's paired with, confirmed by testing Thai text render correctly against the new build. `render.worker.ts` gained one flag (`--backend=manifold`) and nothing else — same `noInitialRun`/`FS`/`callMain` API, same loader shape.

This deliberately deepens, rather than avoids, the CGAL/Manifold divergence ADR-0006 already accepted server-side — the two backends can disagree on precision-sensitive geometry. Accepting that for the client too was a real trade, but it actually *removes* an inconsistency rather than adding one: before this, the Viewer (CGAL) and a customer's actual Export (Manifold, via a fresh server-side Render — see ADR-0004/ADR-0005) could already show subtly different geometry for "the same" Configuration; now both agree. [ADR-0001](./0001-always-render-exact-geometry.md)'s actual commitment — always a full, exact evaluation, never OpenCSG's approximate Preview mode — is unaffected, since Manifold is a different exact evaluator, not an approximation; only the parenthetical naming CGAL specifically was stale and is corrected there.

This also simplifies [ADR-0010](./0010-cached-default-preview.md)'s mechanism: that ADR's original reasoning for precomputing the default-Configuration cache via a *headless CGAL* openscad-wasm build (to avoid a second, Manifold-backend pipeline feeding the Viewer) no longer applies now that the client itself is Manifold. The precompute can — and does — reuse the existing native-OpenSCAD-Manifold render-worker Container pipeline already proven in production for Render on server and Export, rather than vendoring and debugging a separate headless-WASM-in-Node path. See ADR-0010's own text for the current, simplified mechanism.
