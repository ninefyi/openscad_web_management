# Manifold geometry backend for server-side Render, CGAL stays for the client-side preview

The server-side Render (render-worker's Container, used for Export and Admin Publish validation) now runs OpenSCAD's `--backend=manifold` instead of the default CGAL backend. Measured against the Thai character-roller template that originally motivated this — 43 engraved `text()` cuts differenced out of a cylinder at `$fn=160` — Manifold rendered it in 0.47s where CGAL took 90.1s. This isn't a marginal tuning gain: it's the difference between "usable" and "effectively broken" for genuinely complex Templates.

This means running a different, less mature engine than openscad-wasm's client-side preview does (openscad-wasm is frozen at the `openscad-wasm` project's 2022-03-20 release, from before Manifold existed upstream — see CONTEXT.md's parity-discipline note). The two engines can now disagree: Manifold uses single-precision floats internally, versus CGAL's exact-rational arithmetic, so a Template geometrically borderline enough to be precision-sensitive could in principle Render successfully in the browser Preview and differ subtly — or vice versa — through server-side Export. OpenSCAD's own maintainers consider Manifold's precision "graduated" enough to ship as the eventual default, and its speed at scale is the whole point of doing this server-side at all, so the trade-off is accepted for Export/Publish. It's not extended to the client-side Preview in the same change — that's a separate, larger decision (no official Manifold-enabled `openscad-wasm` build exists to swap in; getting one means an in-house Emscripten build with ongoing maintenance cost) and is tracked separately rather than bundled into this one.

Getting this backend requires `openscad-nightly` from the `home:t-paul` OBS repo (see `render-worker/container/Dockerfile`) — Debian's own packaged `openscad` is still 2021.01, years before Manifold existed. The nightly package still defaults to CGAL even now, so `--backend=manifold` has to be passed on every render call (`render-worker/container/server.js`); the older `--enable=manifold` spelling from Manifold's early "experimental" days is obsolete and silently falls back to CGAL instead of erroring, which would have made this fail quietly rather than loudly.
